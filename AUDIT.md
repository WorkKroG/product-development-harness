# Аудит основы и опыта Recipes

Источник для ссылок S1–S7: [SOURCES.md](SOURCES.md).
«Наблюдалось» означает конкретный случай; «утверждено» — решение владельца/принятый workflow;
«предложение» — новая конструкция v0.1, которую ещё нужно проверить.

## Сильная основа: сохранить

S1 уже покрывает путь от проблемы до обратной связи, применимость коммерческой экономики,
проверяемые результаты этапов, отделение фактов от гипотез, failure/recovery/permissions,
необходимость обновлять существующие артефакты и продолжать с первого незакрытого этапа.
Эти возможности не нужно заменять новым процессом или заново изобретать.

S2 добавляет независимое ревью плана и реализации, иерархию модулей, GitHub evidence,
native handoffs и восстановление. Нужно встроить их в S1 с устранением дублирования.

## Что относится к профилю продукта

Гитхост/репозиторий, стек и команды, коммерческий режим и экономические цели, поддерживаемые
устройства, источники требований, owner, release target, текущие модели и доступные инструменты.
Матрица Recipes сохраняется как стартовый согласованный профиль, не как обещание наличия моделей навсегда.
Конкретное состояние branch protection не переносится: его проверяют у целевого репозитория.

Отдельный navigation-only Work Item сохраняется как решение Recipes.
Для нового продукта это необязательный отдельный PR: навигацию можно включить в запланированный
документационный scope существующего Work Item, если это не меняет его границы и проходит review.
Независимая проверка применимости этого упрощения включена в E18.

## Что не переносить

- Рецепты, масштабирование ингредиентов, конкретные actors/API/схемы, технический стек.
- Исторические ссылки на «текущий» main как долговременный факт.
- Автоматизацию ожидания без причины и повторяющиеся уведомления о нормальном in_progress.
- Дополнительный технический approval на каждый простой шаг.
- Требование копировать весь жизненный цикл во все продуктовые репозитории.
- Предположение, что private-repo ограничения Recipes действуют на любой GitHub-план.
- Runtime IDs, auth credentials, исходные переписки и настройки личной машины.

## Не доказано опытом Recipes

Полный запуск нового продукта с этим harness; пригодность всех финансовых defaults для разных
продуктов; завершённый whole-Task FINAL по новому процессу; unattended работа при выключенном
desktop; перенос на чистую установку; выпуск production и фактическое восстановление после аварии.
Эти пункты остаются сценариями пилота, а не маркетинговыми утверждениями о готовности.
